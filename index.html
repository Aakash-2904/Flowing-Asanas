Flowing Asanas

Enhancing Yoga Posture Detection with BiLSTM Attention and MediaPipe

Dr. Noel Jeygar Robert V, P. Aakash Kumar, Abha Rani, Shraddha Pandey

School of Computer Science and Engineering, Vellore Institute of Technology, Chennai

An ordinary RGB webcam, 33 MediaPipe landmarks per frame and a 66.6K-parameter BiLSTM-Attention classifier. Together they check whether you are holding an asana correctly, and a hold timer runs only while you are.

  • 95.0%± 3.0% accuracy under simulated webcam perturbations
  • 33landmarks, 66-d feature vector
  • 4trained asanas

Live demo

Running on an ordinary laptop webcam

The gesture-controlled interface: choose an asana and a hold time with your fingers, then match the reference stick figure. The timer runs only while the pose is held correctly, and the app returns to the menu for the next asana.

01 · System architecture

From webcam frame to posture-aware timer

Steps 1–4 produce a trained model: each webcam frame runs through MediaPipe Pose, the 33 landmarks become a 66-value vector of (x, y) offsets from the nose, and the BiLSTM-Attention classifier maps that skeleton to an asana. The live session then follows one straight path: show fingers to pick the asana, raise fingers again to pick the hold time, then hold the pose. The timer moves only while the model sees the chosen asana with confidence above 75%, and stops as soon as it doesn't.

Frame gating

A frame is used only when inFrame() passes, meaning both wrists and both ankles have visibility > 0.6. Otherwise the demos ask you to make sure your full body is visible, and the timer pauses.

Translation invariance

Subtracting the nose position from every landmark removes where the person stands in the image. The BiLSTM notebook also divides by torso length, so the distance to the camera drops out too.

Confidence threshold

All three live scripts accept a prediction only if its top softmax probability is above 0.75. Lower-confidence frames count as “wrong or not trained”.

Hover over or tap any point to see its name, its position in the 66-value vector, and what the app uses it for. The figure faces the camera, so the person's right side is on the left of the image. Dashed rings mark the four joints inFrame() checks. Pick Torso length to see how the notebook scales every skeleton by the shoulder-to-hip distance.

03 · Main model

BiLSTM-Attention over the skeleton

Given a single 66-value vector as one time step, an LSTM has nothing to recur over. The notebook instead reshapes each frame into a sequence of 33 joints × (x, y). The BiLSTM reads the body joint by joint in both directions, and an additive attention layer learns which joints matter for each pose. This is the model proposed in the paper and the one behind every reported result; a Dense MLP is kept only as a baseline for comparison.

Attention layer

For BiLSTM outputs ht (t = 1…33 joints):

score_t = vᵀ · tanh(W · h_t + b)
α       = softmax(score)        # over the 33 joints
context = Σ_t α_t · h_t          # (B, 128)

The layer returns both context and α. A second Keras model (attention_viewer) shares the weights and outputs α, so you can inspect which joints the classifier relies on.

Baseline for comparison: Dense MLP

A plain multilayer perceptron on the raw 66-value vector, with no joint structure and no attention (models/model_001.h5, trained by src/train_dense.py):

66input 128tanh 64tanh 4softmax

The script trains on all of data/poses/ (shuffled, no held-out split) with RMSprop and categorical cross-entropy for 80 epochs. The notebook retrains the same 128 → 64 → softmax shape with Adam on the augmented, time-split data so the two models can be compared fairly. That is about 17.1K parameters (my count from the layer sizes; the notebook does not print one).

Preprocessing

to_sequence() reshapes (N, 66) → (N, 33, 2) and divides every frame by its torso length, the distance from the shoulder midpoint (11, 12) to the hip midpoint (23, 24). This makes the features scale-invariant.

seq   = flat.reshape(N, 33, 2)
torso = ‖mid(11,12) − mid(23,24)‖
seq   = seq / max(torso, 1e-6)

Time-ordered split

Neighbouring webcam frames are almost identical, so the frames of each pose are split in recording order:

train 60%val 15%test 25%

That gives 192 / 48 / 84 frames (48 / 12 / 21 per pose) out of 324 (81 per pose). Test frames come from a later part of each recording.

Training setup

  • Augmentation15 copies per training frame (192 → 3,072): rotation ±8°, scale ±10%, jitter σ ∈ [0.01, 0.15]
  • OptimiserAdam, lr 1e-3, sparse categorical cross-entropy
  • Schedule100 epochs max, batch 32, EarlyStopping (patience 15), ReduceLROnPlateau (×0.5, patience 6)
  • Seed42 (Python, NumPy, TensorFlow)

Read these numbers honestly

  • Small, single-subject dataset. It has one person, one room, 81 frames per pose and four poses. High accuracy shows that these four poses can be separated. It does not show that the model generalises to new people, camera angles or more asanas.
  • Perfect clean scores are optimistic. On the unperturbed held-out frames the model gets 84 out of 84 right (accuracy 1.0000). Those frames come from the same session and room as the training data, so the 95.0% figure under perturbation is the one to quote.
  • Remaining errors are mostly confusions between High Lunge and Extended Side Angle, which share a similar leg stance.

06 · Setup and usage

Run it locally

You need Python 3.11, a webcam and room to stand with your whole body in view, from wrists to ankles. The code uses MediaPipe's legacy mp.solutions API (Pose, Hands, drawing utils); newer MediaPipe releases have removed it, so install the pinned versions.

1. Open a terminal in the repository folder

cd Flowing-Asanas-ICERCS2024

2. Create and activate a virtual environment

# Windows (PowerShell)
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
# if activation is blocked, run once:
# Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

# Linux / macOS
python3.11 -m venv .venv
source .venv/bin/activate

3. Install dependencies

python -m pip install --upgrade pip
pip install -r requirements.txt

The download is about 1 GB, mostly TensorFlow, and takes a few minutes.

4. Check the install

python -c "import tensorflow as tf, mediapipe as mp; print(tf.__version__, mp.__version__, mp.solutions.pose.Pose)"

It should print 2.15.1 0.10.14 and a Pose class.

5. Run a demo

python src/inference_timer.py

Stand back until your wrists and ankles are in frame, hold a trained asana and watch the timer. Press Esc to quit. The other scripts are listed under Commands below.

6. Measure inference time (optional)

python src/benchmark_inference.py --source webcam

Prints per-stage latency and FPS, and updates docs/benchmark_results.js. Reload this page to see the new numbers. Without --source it uses synthetic frames. For stable numbers, close other programs and plug the laptop in.

7. Open this documentation

# Windows
start docs\index.html

Troubleshooting

  • “Could not read a frame from the webcam”: another app (Zoom, Teams, the Camera app) is using the camera, or camera access is turned off in Windows Privacy settings.
  • Nothing is predicted: the script only classifies when both wrists and both ankles are visible. Step back from the camera.
  • No module named tensorflow: the virtual environment isn't active. Run the activate command from step 2 again.
  • Loading bilstm_attention.keras fails with “Cannot deserialize object of type Attention”: define the notebook's Attention class before calling load_model.

Gesture controls

  1. Pick the asana. The panel on the right lists the trained asanas with a number beside each. Show that many fingers on one hand and hold them still for 1.5 s; a progress bar fills as you hold. Or press 1–4. The panel then switches to the asana's English and Sanskrit names and a reference stick figure of the target pose. The figure is drawn from the median of each of the 33 landmarks over that asana's recorded frames in data/poses/, with left limbs in blue and right limbs in orange.
  2. Set the hold time. Lower your hand first, so the asana gesture is not read again. Then show 1–5 fingers for 10, 20, 30, 45 or 60 s and hold them still, or press 1–5.
  3. Countdown. A 5-second “Starting in” countdown runs, then the timer starts. It counts only while you hold the chosen asana with confidence > 0.75, and pauses and resumes when you break and recover the pose. After “Asana Completed!” a 3-second countdown returns you to step 1 to choose the next asana.
  4. Go back. Chose the wrong asana or hold time? Press B (or Backspace), or hold up both hands for 1.5 s. From the hold-time step this returns to the asana menu; from the countdown or while posing it returns to the hold-time step, and pressing Back again reaches the menu. While posing, the two-hands gesture only works when you step closer so your full body is out of frame, so arms raised in a pose such as High Lunge can't trigger it. The timer resets when you go back.

Finger counting uses the first detected hand. Each of the index, middle, ring and little fingers counts if its tip (8, 12, 16, 20) is above its base joint (5, 9, 13, 17). The thumb counts if its tip (4) is left of the wrist (0) in image x. One hand therefore gives 0 to 5. The screen shows the live finger count, so you can see what the camera reads.

Timer behaviour

pose correct, conf > 0.75wrong pose / body not visible
  • inference_timer.pyThe timer accumulates time while the predicted pose is a trained asana with confidence > 0.75. It pauses when the pose is wrong or the body leaves the frame and resumes on the same total. At 2:00 it shows “2 minutes complete!” and resets.
  • inference_gesture_select.pyCounts up to the chosen hold time only while the prediction equals the chosen asana with confidence > 0.75, then shows “Asana Completed!”. A broken posture shows “Perform the asana correctly” and pauses the timer; it resumes from the time already held once the pose is correct again.

07 · Limitations and next steps

What this does and doesn't show

Limitations

  • The dataset is small and self-collected: one subject, one environment, 81 frames per pose, four poses.
  • Perfect clean-test scores show the four poses are easy to separate. They don't show generalisation to new people, camera angles or more asanas.
  • The BiLSTM runs over the 33 joints of a single frame, not over time. Each prediction is independent of earlier frames.
  • The live demo scripts, and the demo video, currently load the Dense baseline checkpoint (models/model_001.h5), not the BiLSTM-Attention model (models/bilstm_attention.keras). All reported accuracy figures are for BiLSTM-Attention.

Next steps

  • Run BiLSTM-Attention in the live demos (about 8 ms per frame as a compiled tf.function in the benchmark)
  • More asanas and more subjects
  • Joint-angle features
  • Per-joint corrective feedback
  • Sequence models over windows of frames (temporal modelling)
